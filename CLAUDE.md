# Spectra Instructions

This project uses Spectra for Spec-Driven Development(SDD). Specs live in `openspec/specs/`, change proposals in `openspec/changes/`.

## Use `/spectra-*` skills when:

- A discussion needs structure before coding → `/spectra-discuss`
- User wants to plan, propose, or design a change → `/spectra-propose`
- Tasks are ready to implement → `/spectra-apply`
- There's an in-progress change to continue → `/spectra-ingest`
- User asks about specs or how something works → `/spectra-ask`
- Implementation is done → `/spectra-archive`
- Commit only files related to a specific change → `/spectra-commit`

## Workflow

discuss? → propose → apply ⇄ ingest → archive

- `discuss` is optional — skip if requirements are clear
- Requirements change mid-work? Plan mode → `ingest` → resume `apply`

## Parked Changes

Changes can be parked（暫存）— temporarily moved out of `openspec/changes/`. Parked changes won't appear in `spectra list` but can be found with `spectra list --parked`. To restore: `spectra unpark <name>`. The `/spectra-apply` and `/spectra-ingest` skills handle parked changes automatically.

## Project

Z2/4×4 Trainer — iPhone + Apple Watch cardio coach prescribing Zone 2 and Norwegian 4×4 training. Local-only (no server/account); inputs from manual entry or Apple Health. `PROGRESS.md` is the single source of truth for build progress — update and commit it at the end of every work session.

## Commands

```sh
# Domain core — runs on Mac, no simulator needed
cd SharedCore && swift test
cd SharedCore && swift test --filter <TestClassOrMethodName>   # single test

# Regenerate the Xcode project after editing project.yml (required before any xcodebuild)
xcodegen generate

# iOS app build + unit tests (Tests/ runs under the Z24x4Trainer scheme)
xcodebuild -project Z24x4Trainer.xcodeproj -scheme Z24x4Trainer \
  -destination 'platform=iOS Simulator,name=iPhone 16' build
xcodebuild -project Z24x4Trainer.xcodeproj -scheme Z24x4Trainer \
  -destination 'platform=iOS Simulator,name=iPhone 16' test

# watchOS app build
xcodebuild -project Z24x4Trainer.xcodeproj -scheme Z24x4TrainerWatch \
  -destination 'generic/platform=watchOS Simulator' build

# Archive + export + upload to App Store Connect (headless; needs ASC API key env vars
# documented at the top of the script)
scripts/archive-and-export.sh [--upload]
```

`Z24x4Trainer.xcodeproj` is generated by xcodegen from `project.yml` — never edit the .xcodeproj directly; change `project.yml` and regenerate. New source files under existing target directories (`App/`, `Watch/`, etc.) still require `xcodegen generate` to be picked up.

Launch the iOS app with the `-mockHealth` launch argument to get canned Health data for UI smoke tests (no HealthKit permission flow needed).

## Architecture

Five targets (see `project.yml`), all Swift 6.0, iOS 18 / watchOS 11:

- **SharedCore** (Swift package) — domain logic shared by every target: zone math (`HRZoneCalculator`, Karvonen/`ZoneMethod`), session structure (`Norwegian4x4`, `GuidedCue`), planning (`TrainingPlan`, `Targets`, `PlanProgression`), energy (`EnergyCalculator`), analytics (`Readiness`, `FitnessTrend`, `StreakCalculator`, `AchievementEvaluator`). Also holds shared SwiftUI visual tokens (`HRZone+UI`, `IntervalKind+UI`). No HealthKit, no SwiftData — fully unit-testable on Mac via `swift test`.
- **Z24x4Trainer** (iOS app) — SwiftUI + SwiftData. Key seams:
  - `App/Health/HealthProviding` protocol with `HealthKitService` (real) and `PreviewHealthService` (mock, used by `-mockHealth`).
  - `App/Persistence/` SwiftData records (`ProfileRecord`, `WorkoutLog`, `AchievementRecord`).
  - `App/Sync/PhoneSessionReceiver` receives finished workouts from the watch over WatchConnectivity (payload type: SharedCore `WorkoutTransfer`).
  - `App/WidgetSnapshotWriter` serializes SharedCore `WidgetSnapshot` into the App Group (`group.ca.logolo.z24x4`) — the only data channel to widgets/complications.
  - `App/DesignSystem/` — Theme, components, motion; all screens build on these.
- **Z24x4TrainerWatch** (watchOS app, runs independently) — live workout: `WorkoutSessionManager` (HKWorkoutSession), `IntervalEngine` (4×4 phase machine + haptics), `WorkoutSync` sends results to phone.
- **Z24x4Widgets** / **Z24x4WatchComplications** (extensions) — read-only views over the App Group snapshot.

Localization uses String Catalogs (`Localizable.xcstrings` in both `App/` and `SharedCore/`); regions en, zh-Hant, es, ja. User-facing strings must go through the catalogs.
